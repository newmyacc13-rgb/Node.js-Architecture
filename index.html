The latency illusion

Every engineering team eventually hits the same wall. Database queries are optimized, indexes are tuned, Redis sits at sub-millisecond latency, and yet p99 continues to climb. The dashboard shows green across every infrastructure panel. The APM traces look clean. But users feel it — that subtle, inconsistent drag.

In our case, the culprit wasn't network. It wasn't the database. It wasn't even the cache. It was the JSON.stringify() and JSON.parse() calls sitting on the request path, silently competing with everything else on the event loop[reference:0]. At scale, serialization stops being a rounding error and becomes your top CPU consumer.

This is the architecture we shipped to fix it — a hybrid cache serialization layer that reduced p99 by 63% without touching a single business logic branch.

Serialization: the invisible tax

A typical Node.js API request path looks deceptively simple: fetch from cache, deserialize, maybe hit the database, serialize the response. Two serialization boundaries per request. At 50K QPS with 80KB average payloads, that's roughly 8 GB/s of string allocation and garbage collection pressure — on the main thread[reference:1].

The problem compounds because serialization happens twice in the common pattern: once to write into Redis, once to write the HTTP response. Teams rarely notice because each step individually seems cheap. At scale, it becomes the dominant cost.

The fix isn't to remove the cache — it's to remove the serialization boundary from the hot path entirely.

V8 hidden classes & inline cache stability

Before we talk about the cache layer, we need to talk about the objects flowing through it. V8 uses hidden classes (internally called Maps) and inline caches to optimize property access. When an object's shape changes — through conditional property addition, deletion, or inconsistent construction — V8 deoptimizes the call site from monomorphic to polymorphic, then megamorphic[reference:2].

At 2026 request volumes, a megamorphic property access in a hot DTO path costs more than the database call it replaced.

Hidden class churn in DTO construction

Conditional property assignment creates a new hidden class transition per branch. Across thousands of request shapes, this fragments the inline cache until it loses its fast path entirely.

Hybrid cache design: structured clone + binary framing

The core idea: stop paying for JSON on the hot path. Instead of storing serialized strings in Redis, we store ArrayBuffer payloads produced by structuredClone and a compact binary framing layer. The cache holds shapes, not strings.

For responses destined for the wire, we keep a pre-serialized JSON buffer alongside the structured representation. Cache hits return the buffer directly — zero parse, zero stringify. Cache misses populate both representations in one pass.

After
